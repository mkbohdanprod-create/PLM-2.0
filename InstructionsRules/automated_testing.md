# Автоматизоване Тестування (Automated Testing)

Цей документ описує існуючі автоматизовані тести в проєкті, їхнє розташування, призначення та інструкції з їх запуску. Тести допомагають переконатися, що під час додавання нового функціоналу ми не зламали існуючий (регресійне тестування).

## 1. End-to-End (E2E) Тести Фронтенду

Для автоматизованого тестування інтерфейсу (E2E) використовується фреймворк **Playwright**. Він запускає прихований браузер Chromium і проходить визначені сценарії як реальний користувач.

### Запуск тестів
Щоб запустити тести, виконайте команди в терміналі:
1. Перейдіть у папку фронтенду: `cd frontend`
2. Швидкий запуск у фоні (headless): `npm run test:e2e`
3. Запуск з графічним інтерфейсом для налагодження (візуально видно всі кліки): `npm run test:e2e:ui`

### Перелік наявних E2E тестів

Усі E2E тести знаходяться у директорії: `C:\hhgh\PLM module\frontend\tests\`

#### 1. `logistics-workspace.spec.ts`
**Що тестує:** Базовий функціонал "Робочого столу диспетчера" (PLM).
- **Сценарій 1 (Завантаження ядра):** Завантажує головну сторінку (`/plm/`) та перевіряє, що основні компоненти (CalendarPanel, OrdersList) не спричинили фатальних React-помилок і відобразили базову структуру сторінки.
- **Сценарій 2 (Глобальні налаштування):** Симулює натискання на іконку "Налаштування" (SettingsDrawer), очікує відкриття бокового меню та перевіряє наявність ключових вкладок, зокрема нової вкладки "Трудозатрати замір".

## 2. Як додати нові тести

Якщо агенту необхідно написати автотест для нового модуля (наприклад, "Робочого столу конструктора" або "Робочого столу замірника"):
1. Створіть новий файл у папці `frontend/tests/` з розширенням `.spec.ts` (наприклад, `engineer-workspace.spec.ts`).
2. Використовуйте імпорти `@playwright/test`.
3. Завжди намагайтесь писати стабільні селектори (наприклад, шукати по тексту `text=...` або ролям, а не просто по CSS-класам, які можуть змінитись).

*Документ буде доповнюватись по мірі написання нових E2E або Unit тестів для бази даних (pgTAP) чи бекенду.*
